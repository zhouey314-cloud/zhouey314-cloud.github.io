01这是什么

长录音处理的难点，不止是得到一份文字。中断后怎么续跑，改过的文字会不会被覆盖，摘要究竟用了哪些段落，同样影响这份资料能否继续使用。

Ethan Local Tingwu 是我搭建的 Mac 本地转写、回听、校对与引用整理工作台。项目从本地原型持续迭代到单机 Beta；我负责把识别、任务状态、人工修改、分析与交付接成可检查的流程。

使用情境
整理访谈、长音频和个人资料；先保留原始内容，再进行回听、校对与引用整理。
技术组成
Python 后端、网页工作台、Whisper.cpp / Metal、本地分析服务与独立的数据存储。识别模型和推理框架来自开源生态，不是本人训练。
运行范围
本机日常入口已应用 0.3.1-local-beta / schema 5；没有公开源码仓库，也没有对外托管的上传服务。

02看结果

现有本地原型已具备以下处理路径。本页不连接我的本机服务，不接收访客的录音。

  1. 导入并决定是否创建新版本

    相同原音哈希默认打开已有录音；需要重识别时显式创建新版本。热词、声道和引擎配置随任务冻结，避免旧结果混入新设置。

  2. 观察任务，取消后继续

    长录音分块处理，保存源区间、解码帧数、原始 ASR 响应哈希和提交状态。取消后保留已完成块，恢复时复用，而不是从零开始。

  3. 回到声音，逐项修订

    点击文字或引用定位播放器，全文搜索覆盖保存内容。文字、说话人、起止时间、备注和核对状态可分别修改；保留原稿，支持撤销重做。

  4. 整理后导出当前保存版本

    逐字稿可导出 MD、TXT、JSON、SRT、VTT；保存内容支持 PDF、DOCX 与归档。归档保留引用和修订记录，不打包原录音或声纹向量。

这里展示的是工程说明，不是识别效果演示。未经授权的真实录音、逐字稿和私人导出未作为作品素材公开。

03我做了什么

我把可恢复性、人工修改和结果来源放在同一套数据流程里。

任务层
backend/longform.py 规划分块、指纹与覆盖；backend/worker.py 执行任务、保存检查点并复用完成块。输入哈希与处理参数参与缓存判断，保留每个块的来源证据。
校对层
用字段保护、拆句来源追踪和撤销记录区分识别原稿与人工保存内容；对应回归覆盖任务会话、字段锁和分段修改。
分析层
backend/llm.py 逐窗处理保存片段，记录输入覆盖和引用索引。缺块不称整场完成，失败保留旧纪要和本次部分结果。
交付层
backend/content_exports.py 根据当前保存版本导出，区分部分、过期和完整状态；日志按白名单脱敏。

这些是工作台与流程实现的贡献。ASR 引擎、声学编码器和本地模型是集成依赖，不能把模型本身的能力算成本人自研。

04关键选择

  1. 用任务指纹换可恢复性

    只用文件名不足以识别处理结果。同一录音的模型、热词或声道改变后应成为明确的新版本；旧任务保留原策略，不在后台重算。

  2. 让建议停在“候选”

    默认快速读稿不自动认人；多人路线保留匿名声学候选。相似度不当作身份概率，不自动猜姓名，也不建立跨录音实名声纹库。

  3. 输入覆盖与语义质量分开

    逐窗消费全部保存片段，只能证明输入被处理。摘要是否忠实、遗漏了什么，仍需对照原文和声音；覆盖完整不等于零错误。

  4. 本地处理也要管好运行边界

    清理按进程所有权判断，避免误停其他模型实例；升级保留备份与恢复路径。源码安装包不附带模型权重和完整运行库。

05成果与限制

本轮核对
2026-11-10 只读健康回读为 0.3.1-local-beta、schema 5、local_only=true、mature_quality_accepted=false；ASR / LLM 依赖可用。未在本轮重新执行推理或项目全套回归。
历史记录
2026-10-31 Mac 应用记录记载 415 项机械回归通过、9 项真实 Metal / CLI 短音频 smoke，以及浏览器和取消恢复检查。数字只属于当时版本和环境，不是今天的重跑结果。
待人工复核
自然录音的文字、术语、说话人和摘要质量缺可信人工金标，当前不可给出准确率结论。真实重叠、相似声音和候选碎片化仍有风险。
待环境验收
干净 Mac 安装、Safari、Word 原生分页、签名公证、其他系统与多设备使用尚未全面验证。

机械回归、依赖可用和输入覆盖均不能代替自然语音质量验收。
