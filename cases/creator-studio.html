01这是什么

创作工具需要保住表达，也要保住每一次拍摄。我的目标是让文稿、原片和剪辑选择能连续交接，处理失败后仍有东西可以继续。

Ethan Creator Studio 是手机 PWA 与 Mac 工作台的个人工具链；EthanCut 是其中独立的本地口播处理与审片工具。项目从本地原型逐步推进，手机创作台现已有公开静态入口，Mac 端继续在本机使用。

面向谁
需要自己写稿、拍摄和审片的个人创作者；先解决一条口播的保存、裁切和交接。
我的部分
自建手机 PWA、项目和素材交接、Mac 薄包装，以及连接本地 ASR、FFmpeg 和审片的流程。
集成部分
Palmier 是第三方时间线编辑器；Whisper 与 FFmpeg 是开源依赖。集成、工程交换和验证属于我的工作，不把编辑器或模型说成自研。

02看结果

已公开的手机 PWA 与本地工具分别展示，不把两者合称为已经验收的完整云产品。

打开公开手机创作台 ↗

  1. 手机：从文稿到原片

    当前 PWA 有文稿保存、提词、录制与本地剪辑入口。保留原片，提供停顿候选、保留 / 恢复 / 撤销、手动字幕和 SRT 导入，以及浏览器能力允许时的 H.264 / AAC 导出。

  2. Mac：导入并继续处理

    本地工作台接收新原片和手机清单，支持项目选择与续开、草稿、审片、任务取消 / 重试，并可连接 Palmier 时间线。

  3. EthanCut：让修改可回看

    通过本地 ASR 与 FFmpeg 整理口播候选、字幕和剪辑结果，再由审片台核对。候选不自动等于最终成片；私人样片未批准公开。

公开静态版没有开放云 ASR、语音跟随或云媒体同步；这些功能不能由按钮、桌面截图或本地分支的存在推断为已上线。

03我做了什么

我主要处理跨步骤的状态、保存和交接问题，让原片和用户选择不在工具切换时丢失。

手机状态
Prompter.tsx、media.ts 与 storage.ts 负责提词、录制和 IndexedDB 分块保存。围绕本地文稿、素材索引和剪辑决定组织 PWA。处理录制中断后的救援、重拍保护、跨标签页录制冲突与更新时的未保存提示。
剪辑链路
LocalStudio.tsx、local-engine.ts 和 interchange.ts 连接编辑、导出与清单交换。把停顿检测作为可撤销候选；字幕随裁切映射，EDL 备份保留剪辑决定，导出后检查格式、音视频流和原片哈希。
Mac 包装
scripts/studio.py 复用 EthanCut 的 scripts/ethancut.py，连接素材导入、项目续开、任务状态与第三方时间线；不重新编写完整非线性编辑器，也不要求把手机原片自动上传到云端。
交付与恢复
分别维护手机公开静态壳与本机工程；保留旧部署、失败记录和素材。入口域名变化时不静默搬迁或清空原有草稿。

04关键选择

  1. 先保留原片，再处理候选

    裁切、字幕和停顿建议都围绕保留原始媒体与撤销路径设计。自动候选让人审查，而不是直接删除内容并宣布剪辑完成。

  2. 把处理留在设备能力范围内

    静态版用本地处理和能力检测，存储与编码不可用时明确提示。桌面浏览器能导出，不代表实体手机具备相同内存或耗时。

  3. 用交换格式连接工具

    手机清单、项目索引和 EDL 传递素材与剪辑决定；Palmier 承担专业时间线，我负责交接与回读，减少重复实现。

  4. 分开发布与拍摄验收

    公开 HTTPS 只证明有可访问入口。相机麦克风权限、国内网络、实拍原片、手机保存与 Mac 接续，需要在实际设备上逐步确认。

历史媒体记录

仍待验收

独立原生 iOS 分支仍需要完整 Xcode 与真机验收；这里的公开入口是 PWA，不把它称为已交付的原生 App。
