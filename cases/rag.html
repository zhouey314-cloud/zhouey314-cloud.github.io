01这是什么

资料查询的交付目标：使用者拿到一段回答时，能核对原文、版本和可见范围；资料负责人能更新、撤销和恢复资料。

我把问题拆成三条路径：资料由可信操作员入库并定义权限；查询者提交问题并读取获授权的当前版本；维护者按运行说明检查数据库、备份和恢复。公开网页单独用于演示查询与来源，不承担身份服务。

交付与验收：本地 CLI / HTTP 服务、MD / PDF / DOCX 入库、版本与来源元数据、失败回归和恢复命令。先试查询与缺资料提示，再按本地复现步骤核对权限、更新和恢复，而不只看页面能否给出一段文字。

03我做了什么

我的责任覆盖资料输入、查询决策、证据回查和运行交接。

数据与接口：我实现多格式解析、文档指纹与递增版本，把文件内容与访问/日期元数据一起纳入变更判断。Markdown 保留行位置，PDF 使用解析页码，DOCX 使用段落位置；查询与来源接口都检查身份和当前版本。

回答与失败处理：我把词法检索与可答性检查分开，修复无关首句、标题含词却正文无证据、缺少实际电话/邮箱值等误答。找不到足够证据时保留检索线索，明确返回拒答。

维护与交接：我加入只读健康检查、SQLite 在线备份和独立路径恢复；回归覆盖 WAL 已提交数据、备份时的身份撤销状态、目标覆盖拒绝和不完整副本清理。维护者能按命令复现这些状态。

04工程判断

01 / 先确定资料可见范围，再参与排名

只在返回答案后隐藏不可访问资料，仍可能让其他租户的词频影响 BM25 排名。我采用获授权资料的内存 FTS5 快照，使本次排名只依赖该身份可读的当前资料；代价是它面向有限规模的本地参考场景。

02 / 把权限和版本当作资料的一部分

文件字节相同，权限或生效日期也可能变化，因此变更指纹同时包含内容与安全/版本元数据。来源回查再次检查权限、版本与日期；最新版本不可用时，不退回旧版本补一个答案。

03 / 命中资料和足够回答分别判断

片段可能谈到“联系电话”，却没有号码。词法路径只引用能满足当前问题的原句，缺值时保留线索并拒答；可选语义模式缺少依赖时明确失败，不静默切回词法结果。这样可以区分模式错误、资料缺口与检索漏检。

05验收与交接

一轮验收，应同时走通查询、变更、拒绝与恢复。

建议从一组获授权资料开始：确认常见问题与期望来源，运行入库和查询；再更新文档、调整可见范围、查询缺失值，核对新旧引用与拒答；最后备份到新文件、恢复到独立路径并运行健康检查。通过后，再约定实际业务数据和下一步集成范围。

已有证据：公开工作台可直接核对来源摘录和缺值拒答；本地工程有真实 CLI / HTTP、权限、版本及备份恢复回归，运行与对应固定提交的证据列在下方。

公开工作台使用合成资料做词法检索与原文摘录，未接入生成模型。没有真实企业文档或专家确认的 Golden Set；本地身份不是企业 SSO，词法覆盖也不等于语义理解，真实企业回答质量与生产部署尚未验收。

2026-10-28 的本站工作台记录：复用公开引擎，检查既有 Node 回归；支持导入本地文本、查看原文并导出结果。合成语料检验不代表真实企业回答质量。

06深入查看

2026-10-21 本地版加入 MD/PDF/DOCX 入库、文件哈希和版本、生效/过期日期与更新删除。可信身份由本机管理员签发，服务端保存租户与角色；客户端不能靠选择 scope 或传入 role 冒充身份。

结构：可信身份 → 可访问的当前文档 → SQLite FTS5 与词项排名融合 → 正文可答性检查 → 带版本/页段/哈希的原文摘录。PDF 使用实际页码；DOCX 只标段落，不编造 Word 分页。
