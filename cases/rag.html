01这是什么

知识问答不仅要找到答案，还要过滤权限、给出来源，并在证据不足时拒答。

以合成文档和明确的权限规则构建 RAG 工程样例，区分线上词面 Demo 与独立的本地文件服务。可选 embedding 模式需另行配置，未包含在这组线上截图中。

02看结果

以下为同一公开演示的三个实际浏览器状态。核心问题是：检索到相关文字，是否真的足够回答？

01 / 先把资料范围摆清楚

合成资料的片段带有来源名称、版本和访问范围。这里的 Public / Team 下拉框仅用于演示过滤，不是生产登录。

02 / 让回答回到原始资料

询问退款政策，页面摘录 14 天窗口，并同时显示 returns:0、v1 和来源名称；没有调用生成模型。

03 / 相关，不等于足够回答

询问客服电话会命中支持时间片段，但原文没有电话号码。页面明确返回证据不足，保留命中片段供复核。

03我做了什么

建立文档索引、权限过滤、证据引用与低证据拒答，附本地合成检索评估。

展开技术结构

检索前的访问过滤、引用生成和拒答逻辑独立测试；Python 端提供可运行的本地路径。

04一项关键选择

每种检索模式都先过滤访问范围，再打分；在线词面模式是透明基线，本地 embedding 模式不会失败后悄悄退回词面。

05成果与限制

权限过滤、来源引用与无答案路径都有独立的检查方式。

没有真实企业文档或专家确认的 Golden Set；在线 Demo 只运行词面检索。 独立的本地服务支持 MD/PDF/DOCX 摄取与本机令牌身份，未接入企业 SSO 或托管生产认证。

06深入查看

2026-10-21 本地版加入 MD/PDF/DOCX 入库、文件哈希和版本、生效/过期日期与更新删除。可信身份由本机管理员签发，服务端保存租户与角色；客户端不能靠选择 scope 或传入 role 冒充身份。

结构：可信身份 → 可访问的当前文档 → SQLite FTS5 与词项排名融合 → 正文可答性检查 → 带版本/页段/哈希的原文摘录。PDF 使用实际页码；DOCX 只标段落，不编造 Word 分页。

2026-10-21 工程复核：23 项 Python 与 10 项 Node 测试；4 个词面检索案例和 9 个答案可答性案例分开记录。 查看修复与 CI 记录 ↗

2026-10-21 本地路径记录共48项 Python 测试，原10项 Node 与4/9用例保留。62个合成候选、56种问法：全部候选满足预期60/62，Recall@1/@3为38/40，原文摘录一致38/40，引用源完整性38/38，拒答 precision 22/24、recall 22/22。用户已确认审阅62条；2个语义改写漏检继续计入结果，没有把候选集当作真实企业准确率。
