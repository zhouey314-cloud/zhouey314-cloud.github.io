01 / Problem

知识问答不仅要找到答案，还要过滤权限、给出来源，并在证据不足时拒答。

02 / Context

以合成文档和明确的权限规则构建 RAG 工程样例，区分线上词面 Demo 与本地语义模式。

03 / Constraints

公开数据为合成材料；在线页面不是生产 RAG 服务。本地 embedding 模式需要额外环境。

04 / Architecture

检索前的访问过滤、引用生成和拒答逻辑独立测试；Python 端提供可运行的本地路径。

05 / Engineering Decisions

每种检索模式都先过滤访问范围，再打分；在线词面模式是透明基线，本地 embedding 模式不会失败后悄悄退回词面。

06 / Implementation

建立文档索引、权限过滤、证据引用与低证据拒答，附本地合成检索评估。

07 / Tests

19 项 Python 单测和 4 个合成词面案例通过；线上浏览器检查了抽取式答案、来源引用与无答案路径。

08 / Evaluation

检索命中、引用、权限与拒答分开检查。现有案例为 synthetic_unverified；没有生成式 LLM 答案质量分数。

09 / Demo

可运行入口：https://zhouey314-cloud.github.io/enterprise-rag-starter/。这是公开演示/样本，不等于生产部署或用户验收。

10 / Limitations

无真实企业文档、真实认证、PDF 摄取或专家确认的 Golden Set；在线 Demo 只运行词面检索。

11 / What Worked

权限、来源与拒答成为明确的工程关口。

12 / What Failed

合成评估不能证明真实企业知识库上的检索或回答质量；线上与本地能力不等同。

13 / Lessons

先分开检索正确性与生成回答质量，避免用 API 成功替代效果评估。

14 / Next Steps

引入获授权的真实失败样本、人工标注与端到端回归。
