01这是什么

Agent 仍然正常使用，网关只观察可见信息。

项目让 Agent 请求经本地网关转发到用户配置的 API，默认 passive 模式不会额外发送模型请求。它观察声明标签、协议错误和服务变化，独立输出告警和报告。

02看结果

已经有可复现的合成链路演示。

2026-10-23 按公开命令实际运行了本机模拟 Agent 与模拟中转：3 次请求、3 次上游转发、0 次额外模型请求，标签变化后产生一条告警，后续请求继续完成。下面是这次生成的原始报告排版截图。它证明本次合成告警路径，不证明真实中转商更换了模型。

03我做了什么

拆出协议观察、证据、告警与恢复流程。

公开仓库提供协议检查、流式数据保真、本机通知、状态管理、报告和受限配置方式。演示环境及测试记录可从仓库复核；本站不重跑模型服务。

04一项关键选择

不把“异常”误写成“识别到假模型”。

模型声明变化只是标签不符合预期；协议错误可能来自网关、模型或参数；性能变化是描述性现象。即使可见标签不变，也不能据此证明真实模型身份。

05成果与限制

已经跑通模拟检测，真实模型身份仍未校准。

真实客户端连到模拟端点有接入验收；尚无真实中转站模型身份指纹与校准准确率。数据不足应当显示数据不足。被动模式不等于零延迟，开启复核请求也不等于金额硬预算。

2026-10-21 记录的125项测试保留上述修复，并覆盖取消、超时、背压、非法 Content-Length 与并发。观察队列丢失时仍保留已知的真实传输终止原因，不把超时或取消改写成“不可观察”。

同批合成 JSON/SSE 请求比较直连、关闭观察与完整 passive。C1每模式100次、C8每模式200次：实体哈希一致，额外请求、HTTP/实体错误与队列丢失均为0。开销没有被隐藏：本机 C8 SSE 的 p95 从直连9.126ms变为完整观察21.178ms；这是固定顺序的 loopback 小样本，不是生产容量或低开销保证。
