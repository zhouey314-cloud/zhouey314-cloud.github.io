01 / Problem

AI 项目常把夹具、接口和 JSON 格式通过误报为模型质量通过。

02 / Context

构建可复用的评估工程骨架，明确数据来源、失败分类与发布闸门。

03 / Constraints

当前公开案例是合成夹具；没有独立验证的真实业务 Golden Set。

04 / Architecture

JSONL 案例、校验器与报告流程分层；用确定性测试保证评估管道自身正常工作。

05 / Engineering Decisions

把 FIXTURE_SCHEMA_PASS 和 MODEL_QUALITY=NOT_RUN 分开输出；高风险失败不能被综合分数遮盖。

06 / Implementation

提供案例 schema 校验、基线/回归说明与 release gate 文档。

07 / Tests

五个合成案例的完整选择器与单元测试通过，检查案例结构、来源标签和重复 ID。

08 / Evaluation

当前运行只验证夹具与来源标注。未接真实模型、独立真值或人工评审，模型质量门槛仍为 NOT_RUN。

09 / Demo

可运行入口：https://github.com/zhouey314-cloud/ai-eval-engineering。这是公开演示/样本，不等于生产部署或用户验收。

10 / Limitations

没有可报告的模型正确率、延迟、成本或真实业务结果。

11 / What Worked

能如实区分评估基础设施与模型能力。

12 / What Failed

无可信人工真值或实际模型运行时，不能给出质量分数或上线结论。

13 / Lessons

评估首先要保护证据来源和失败记录，不能由同一 AI 自写题、自判题、自宣布成功。

14 / Next Steps

由领域人员审核样本，接入实际模型输出并持续记录回归。
